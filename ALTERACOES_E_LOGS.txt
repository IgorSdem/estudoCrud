4. ALTERACOES DE SENHA E SEGURANCA
============================================================

Antes:

- O login comparava email e senha diretamente no banco.
- A senha provavelmente ficava salva em texto puro.

Depois:

- Senhas novas sao salvas com hash usando crypto.pbkdf2Sync.
- Formato salvo:
  pbkdf2$iterations$salt$hash

- Senhas antigas em texto puro ainda funcionam.
- Quando um usuario com senha antiga faz login, o sistema tenta migrar a senha para hash.
- A migracao de senha agora tem tratamento de erro para nao derrubar o servidor.

Problema encontrado:

- O MySQL retornou:
  Error: Data too long for column 'senha' at row 1

Causa:

- A coluna senha estava curta demais para guardar o hash seguro.

Correcao aplicada:

- Ao conectar no banco, o sistema tenta executar:
  ALTER TABLE usuarios MODIFY senha VARCHAR(255) NOT NULL;

- Se o ajuste automatico falhar, o servidor exibe no console a instrucao SQL para executar manualmente:
  USE sistema_login;
  ALTER TABLE usuarios MODIFY senha VARCHAR(255) NOT NULL;
